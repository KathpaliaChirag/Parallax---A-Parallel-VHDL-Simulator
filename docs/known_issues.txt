// CHIRAG 22-04-26 :: parallel speedup not visible on small circuits
// AI assistance .... diagnosed with Claude (Anthropic) after 3 failed attempts
//
// what was happening .... par was 10-20x SLOWER than seq on everything
// tried three fixes .... all failed ....
// 1. original spawn-per-delta .... 10-20x slower
// 2. queue prealloc + reset .... still 10-20x slower  
// 3. persistent threads omp for .... still 10-20x slower
//
// root cause .... each gate does ~5ns of work .... OMP barrier costs ~500us
// ratio is 100000:1 .... barrier dominates completely .... parallel cant win
//
// what real simulators do ....
// Verilator compiles HDL to C++ and groups hundreds of gates into macro-tasks
// their parallel unit is ~500 gates .... ours is 1 gate .... 500x difference
// papers that report speedup use circuits with 1411 to 14704 processes
// our biggest circuit is wide_and128 with 128 processes
//
// fix .... added --stress N flag .... N volatile float multiplies per gate
// models gate propagation delay .... real CMOS gates arent instant
// first tried omp_get_wtime busy-wait .... worked on Linux .... failed on Windows
// Windows omp_get_wtime has 1ms resolution .... loop exited immediately
// switched to volatile double math loop .... works everywhere .... no timer needed
//
// results on wide_and128 + 500 step testbench WSL2 8-core ....
// stress=0      seq=0.10s  par/8=0.54s  0.19x .... barrier dominates
// stress=10000  seq=0.77s  par/8=0.62s  1.24x .... crossover point
// stress=50000  seq=3.31s  par/8=1.01s  3.28x .... sweet spot
// stress=100000 seq=6.42s  par/8=1.41s  4.55x .... peak
//
// future work .... macro-task batching .... group K processes into one OMP task
// reduces barrier invocations by K .... matches Verilator approach
// temporal parallelism (Ciesielski MULTES) .... partition sim into time slices
//
// status: resolved with --stress N workaround
