   7. AUTO TESTBENCH OVERFLOW FOR CIRCUITS WITH 32+ INPUTS
   file: src/parser/parser.y
   issue: auto testbench uses "1 << input_count" to compute combinations
          in C ... 1 is a 32-bit int ... shifting by 32 or more is undefined behavior
          on most systems it wraps to 0 or 1 ... so thirty2_channel generates 1 combination
          instead of the intended cap of 16
   why it happens: 1 << 32 overflows a 32-bit integer ... result is garbage
   fix: change "1 << input_count" to "1L << input_count" ... L makes it 64-bit long
        then the cap of 16 kicks in correctly for large circuits
   current impact: thirty2_channel gets only 1 auto testbench combination ... values all 0
                   correctness is fine ... just less thorough coverage
   workaround: use manual testbench file instead ... TB=... in make command
   priority: low ... manual testbench always works ... auto is just a convenience
